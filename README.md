# nstore — 아임웹 → 네이버 스마트스토어 상품 이전 도구

복지용구(의료기기 포함) 상품 400여 개를 스마트스토어에 옮기면서

1. **키워드·상품명·태그 엑셀 작업** (1단계)
2. **상세페이지 만들기** — 분석·카피·이미지 프롬프트는 Claude(터미널의 Claude Code), 이미지 그리기는 Gemini (2단계)

를 하는 프로그램입니다.

---

## 맥에서 처음 설치하기

터미널(응용 프로그램 → 유틸리티 → 터미널)을 열고 한 줄씩 실행합니다.

1. Homebrew가 없다면 설치 (이미 있으면 건너뛰기)

   ```bash
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   ```

2. 파이썬 설치

   ```bash
   brew install python@3.12
   ```

3. 이 저장소 받기

   ```bash
   git clone https://github.com/yoyo5679/nstore.git ~/nstore
   ```

4. 폴더로 이동

   ```bash
   cd ~/nstore
   ```

5. 가상환경 만들기 (이 프로그램 전용 파이썬 공간)

   ```bash
   python3.12 -m venv .venv
   ```

6. 가상환경 켜기 — **터미널을 새로 열 때마다** `cd ~/nstore` 후 이것부터 실행

   ```bash
   source .venv/bin/activate
   ```

7. 필요한 라이브러리 설치

   ```bash
   pip install -r requirements.txt
   ```

8. 상세페이지를 이미지로 찍을 브라우저 설치 (한 번만)

   ```bash
   playwright install chromium
   ```

9. Claude Code 설치 (이미 쓰고 있으면 건너뛰기)

   ```bash
   curl -fsSL https://claude.ai/install.sh | bash
   ```

10. Claude Code 로그인 — 아래 명령으로 한 번 실행해서 Claude 계정(Pro·Max 구독)으로 로그인한 뒤 `/exit` 로 나옵니다. 이 프로그램은 그 로그인으로 Claude를 부르므로 Claude API 키가 필요 없습니다.

   ```bash
   claude
   ```

11. API 키 파일 만들기

   ```bash
   cp .env.example .env
   ```

12. 키 입력 — 텍스트 편집기가 열리면 값을 채우고 저장

   ```bash
   open -e .env
   ```

### 필요한 API 키

| 키 | 어디서 | 용도 |
|---|---|---|
| `NAVER_AD_API_KEY` / `NAVER_AD_SECRET_KEY` / `NAVER_AD_CUSTOMER_ID` | 네이버 검색광고(searchad.naver.com) → 도구 → API 사용 관리. 광고비를 쓰지 않아도 계정만 있으면 발급됩니다. | 월간 검색수, 연관키워드 |
| `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET` | 네이버 개발자센터(developers.naver.com) → 애플리케이션 등록 → 사용 API에 '검색' 추가 | 경쟁 상품 수, 상위 상품 카테고리 |
| `ANTHROPIC_API_KEY` | (선택) Claude Console → API Keys | Claude를 터미널 대신 API로 쓸 때만 (`claude.backend: api`) |
| `GEMINI_API_KEY` | Google AI Studio | 2단계 이미지 그리기 |

## 실행

```bash
streamlit run app.py
```

브라우저가 열리고 왼쪽 메뉴에 **1단계 · 상품명·등록 엑셀**, **2단계 · 상세페이지**가 있습니다. 같은 일을 터미널 명령으로도 할 수 있습니다(`python -m nstore --help`).

## 1단계: 상품명·등록 엑셀

### ① 아임웹 가져오기

아임웹 관리자에서 상품 엑셀을 받아 올리면 `data/master.xlsx`(마스터 시트)가 만들어집니다.

- 상품명을 보고 **품목**(성인용보행기, 안전손잡이 …)을 자동으로 정합니다. 못 정한 상품은 `품목분류메모`에 이유가 적혀 있으니 엑셀에서 `품목` 칸을 직접 채워 다시 올리세요.
- `브랜드`, `모델명`이 비어 있으면 상품명이 약해집니다. 이 단계에서 채워두세요.
- 아임웹 엑셀의 헤더 이름이 예상과 달라 못 찾은 칸은 화면에 표시됩니다. `config/imweb_columns.yaml`에 그 헤더 이름을 추가하면 됩니다.

### ② 키워드 조사

상품 400개를 하나씩 조사하지 않고 **품목별로 한 번** 조사합니다. 같은 품목 상품은 같은 키워드 풀을 씁니다. 결과는 `data/keywords.xlsx`에 품목별 시트로 저장됩니다.

| 칸 | 뜻 |
|---|---|
| 월검색수 | 최근 한 달 PC+모바일 검색수 (검색광고 API) |
| 상품수 | 네이버 쇼핑에 그 키워드로 나오는 상품 수 |
| 경쟁강도 | 상품수 ÷ 월검색수. 낮을수록 들어가기 쉬움 |
| 카테고리일치율 | 그 키워드 검색 상위 상품 중 우리 품목 카테고리에 있는 비율 |
| 구분 | **메인**(대표 키워드), **세부**(메인+속성어, 예: 접이식성인용보행기), **연관**(같은 뜻의 다른 표현), **제외** |

자동으로 **제외**되는 키워드:
- 카테고리가 다른 키워드. 예를 들어 '보행기'는 아기 보행기가 대부분이라 제외됩니다.
- 타사 브랜드명이 들어간 키워드. 상표권 문제가 있고, 네이버에서도 감점됩니다.

**이 엑셀의 `구분` 칸은 사람이 한 번 검토해 주세요.** 품목이 20개 안쪽이라 시트 20장만 보면 됩니다. 예를 들어 수동침대 시트에 '전동침대'가 연관으로 들어가 있으면 `제외`로 바꿔 화면에 다시 올립니다. 요약 시트의 `추천카테고리`를 보고 `config/items.yaml`의 `category_id`도 채워주세요.

### ③ 상품명·태그

상품명은 `브랜드 + 모델명 + 속성어 + 메인키워드` 순서로 만듭니다. 예: `케어메이트 CM-200 접이식 성인용보행기`

- **메인키워드는 하나만** 넣습니다. 노인보행기·실버카처럼 같은 뜻의 말을 상품명에 나열하면 동의어 반복으로 감점되므로 **태그**로 보냅니다.
- **속성어**(접이식, 경량 …)는 자사몰 상품명·설명에 실제로 그 말이 있을 때만 넣습니다. 확인 못 한 속성은 `확인필요속성` 칸에 적어두니, 맞으면 직접 넣으세요.
- 고칠 상품명과 태그는 `최종상품명`, `최종태그` 칸에 적습니다. 다시 생성해도 이 칸은 지워지지 않습니다.
- `검사결과` 칸에는 규칙 검사 결과가 들어갑니다. 길이, 금지 문구(무료배송·최저가·본인부담금 할인 등), 의료기기 광고 주의 표현(치료·효과·최고 등), 특수문자, 단어 반복을 봅니다. 규칙은 `config/title_rules.yaml`에 있습니다.

### ④ 스마트스토어 엑셀

스마트스토어센터 → 상품 일괄등록에서 **최신 양식**을 받아 올리면 그 양식에 그대로 채워 `output/smartstore_upload.xlsx`로 저장합니다.

- 내보내기 직전에 상품명을 다시 검사해서 **오류가 있는 상품은 빼고** 목록을 알려줍니다.
- 양식에서 못 찾은 컬럼은 경고로 나옵니다. `config/smartstore_columns.yaml`의 헤더 이름을 양식에 맞춰 고치세요. 양식에 예시 행이 있으면 `skip_rows_after_header` 값을 바꿉니다.

## 설정 파일 (`config/`)

| 파일 | 내용 |
|---|---|
| `items.yaml` | 복지용구 품목, 씨앗 키워드, 자동분류용 별칭, 스마트스토어 카테고리 ID |
| `settings.yaml` | 최소 검색수, 카테고리 일치 기준, 상품명 길이, 태그 수 등 |
| `title_rules.yaml` | 상품명 금지·주의 문구 |
| `imweb_columns.yaml` | 아임웹 엑셀 헤더 → 마스터 시트 |
| `smartstore_columns.yaml` | 마스터 시트 → 스마트스토어 양식 헤더 |

네이버 API 응답은 `data/cache.sqlite`에 14일간 저장해 같은 키워드를 다시 부르지 않습니다. 쇼핑 검색 API는 하루 호출 한도가 있습니다. `data/`와 `output/` 폴더는 깃허브에 올라가지 않습니다.

## 2단계: 상세페이지

역할을 나눴습니다.

- **Claude** (터미널의 Claude Code): 자료 분석, 리뷰 분석, 섹션 구성·카피, 말로 고치기, 레퍼런스 분위기 분석, 이미지 프롬프트 작성
- **Gemini (Nano Banana)**: Claude가 쓴 프롬프트와 실사진을 받아 이미지 그리기

상품 하나당 아래 순서로 진행합니다. 화면 오른쪽에 페이지 미리보기가 계속 보입니다.

| 탭 | 하는 일 |
|---|---|
| ① 자료 | 여러 각도 사진, 카탈로그·사용설명서(PDF)를 올립니다. **자료 정리하기**를 누르면 Claude가 자료에 적힌 사실만 뽑습니다(특징, 규격, 구성품, 사용법, 주의사항, 인증). 자료에서 확인하지 못한 항목은 따로 알려주고, 틀린 곳은 직접 고칠 수 있습니다. 고객 리뷰를 붙여넣으면 고객이 좋아한 점과 망설인 점을 뽑아 카피와 FAQ에 씁니다. |
| ② 구성·카피 | 섹션 구성과 카피를 만듭니다. 흐름은 후킹 → 공감 → 해결 → 특징 → 신뢰 → 사용법 → 반박처리(FAQ) → 제품 정보 → 주의사항 → 마무리이고, 1단계 키워드가 들어갑니다. 섹션마다 실사진을 쓸지 AI 연출컷을 만들지, 어떤 장면을 만들지도 정합니다(장면 설명은 한국어). **말로 고치기**는 섹션 하나나 페이지 전체에 할 수 있고, 직접 고치기·순서 바꾸기·삭제와 **되돌리기**도 됩니다. |
| ③ 이미지 | 사용 장면, 디테일 컷, 흰 배경 제품컷, 배경 확장을 만듭니다. Claude가 실사진·섹션 카피·사용법과 주의사항을 보고 영어 프롬프트를 쓰고, Gemini가 실사진을 참고 이미지로 받아 그려서 제품 모양이 바뀌지 않게 합니다. 실제로 보낸 프롬프트는 이미지 아래에서 볼 수 있습니다. 이미지별로 "배경을 거실로"처럼 말로 고치거나 이전 이미지로 돌릴 수 있습니다. **대표이미지**는 흰 배경에 글자 없이 만듭니다. |
| ④ 디자인 | 브랜드 메인 색 하나를 고르면 나머지 색이 맞춰집니다. 마음에 드는 상세페이지 캡처를 올리면 그 페이지의 색·글꼴·분위기를 가져옵니다. 모든 상품에 적용하거나 이 상품에만 적용할 수 있습니다. |
| ⑤ 내보내기 | 스마트스토어 860px, 쿠팡 780px, 토스쇼핑 1,080px 규격과 JPG·PNG·WEBP 형식으로 저장하고 zip으로 받습니다. 섹션별 이미지(스마트에디터에 차례로 올리기 좋음), 전체를 이은 긴 이미지 한 장, 대표이미지 1000×1000이 나옵니다. |

### 글자를 AI 이미지에 넣지 않는 이유

AI가 이미지 안에 한글이나 숫자를 그리면 글자가 깨지거나 규격 숫자가 지어내지는 일이 생깁니다. 그래서 이미지는 사진만 만들고, 헤드라인·본문·스펙표는 HTML 디자인 위에 얹어 그대로 찍어냅니다. 문구를 고쳐도 이미지를 다시 만들 필요가 없습니다.

### 문구 검사 (② 탭 위쪽)

- **금지·주의 표현**: 상품명과 같은 규칙(`config/title_rules.yaml`)으로 검사합니다. 무료·할인·본인부담금 면제, 치료·효과·최고 같은 표현을 잡습니다.
- **자료에 없는 숫자**: 카피에 나온 숫자가 정리된 사실 자료에 없으면 경고합니다. AI가 지어낸 규격을 잡기 위한 검사입니다.
- **의료기기**: 마스터 시트의 `의료기기여부`가 Y인 상품이 대상입니다. 상세페이지는 광고 자율심의 대상이라(심의기구: 한국의료기기산업협회), 심의 문구를 넣기 전에는 **오류**로 표시됩니다. ① 탭에 심의 받은 문구를 붙여넣으면 Claude가 그 문장만 쓰고, 심의 문구에 없는 문장은 경고로 알려줍니다. 페이지 맨 아래에는 허가·신고번호와 광고심의필 번호가 표기됩니다.

### 상품 폴더

사진과 자료는 화면에서 올려도 되고, Finder에서 직접 넣어도 됩니다.

```
products/<상품코드>/
  photos/             여러 각도 실사진
  docs/               카탈로그·사용설명서 (PDF 또는 이미지)
  reviews.txt         (선택) 고객 리뷰
  approved_copy.txt   (의료기기) 심의 받은 문구
  work/               AI가 만든 결과와 되돌리기 기록
```

### 여러 상품 한꺼번에 (터미널)

400개를 화면에서 하나씩 누르기 어려우니, 자료를 폴더에 넣어두고 한 번에 돌린 뒤 화면에서는 검토와 수정만 하면 됩니다.

```bash
python -m nstore detail all --all
```

단계별로 나눠 돌릴 수도 있습니다: `facts`(자료 정리), `plan`(구성·카피), `images`, `thumbnail`, `export`, `check`(문구 검사). 상품코드를 적으면 그 상품만 처리합니다.

```bash
python -m nstore detail plan A1001 A1002
```

한 상품이 실패해도 나머지는 계속 처리하고, 끝에 실패한 상품을 알려줍니다.

`all`은 이미 끝난 단계(자료 정리, 구성·카피, 이미 만든 이미지, 대표이미지)를 건너뜁니다. 그래서 중간에 멈춰도 같은 명령을 다시 실행하면 이어서 진행합니다. 처음부터 다시 만들려면 `--redo`를 붙이세요. Claude 구독 사용 한도에 걸리면 그 자리에서 멈추고 남은 상품 수를 알려주니, 한도가 풀린 뒤 같은 명령을 다시 실행하면 됩니다.

### 모델 설정

`config/settings.yaml`에서 바꿉니다.

- `claude.backend`: 기본 `cli`
  - `cli`: 터미널의 Claude Code(`claude -p`)를 부릅니다. 구독 로그인으로 돌아가고 Claude API 비용이 따로 들지 않는 대신, 구독 사용 한도 안에서 돌아갑니다. Claude Code는 파일 읽기 도구만 쓸 수 있게 제한해서 사진·PDF를 읽기만 하고 다른 파일을 고치거나 명령을 실행하지 않습니다. `.env`에 `ANTHROPIC_API_KEY`가 있어도 이 방식에서는 넘기지 않아서 API로 과금되지 않습니다.
  - `api`: Anthropic API를 직접 부릅니다. `ANTHROPIC_API_KEY`가 필요하고 쓴 만큼 과금됩니다. 한도 걱정 없이 빠르게 돌리고 싶을 때 씁니다.
- `claude.model`: 기본 `claude-opus-5-5`
- `claude.effort`: 기본 `high`. `medium`으로 낮추면 더 빠르고 사용량이 줄지만 덜 꼼꼼합니다. 400개를 구독 한도 안에서 돌리려면 `medium`도 고려해 보세요.
- `gemini.image_model`: 기본 `gemini-nano-banana-2.1`. 구글이 이미지 모델 이름을 자주 바꾸고 예전 이름은 종료하니, 화면 왼쪽 **Gemini 이미지 모델 확인**이나 아래 명령으로 실제 이름을 확인하고 맞춰 주세요.

`api` 방식에서는 Claude가 안전 기준 때문에 요청을 거절하면 서버가 다른 Claude 모델로 자동으로 다시 시도하도록 설정해 두었습니다(fallbacks).

```bash
python -m nstore detail models
```

상품당 Claude 호출은 자료 정리·리뷰 분석·구성 카피 2~3번에 이미지 한 장마다 프롬프트 1번이고, Gemini 이미지는 최대 6장과 대표이미지 1장입니다. 이미지 수는 `max_generated_images`로 줄일 수 있습니다.
